## Latest frontend update

- Date: 2026-11-08. Scope: Home, venue discovery and shell (Lovable `2a32eb05`). `GET /home/` is the only Home-entry request; FE reads the additive `display_name`, `promo_summary.total`, `nearest_venue` and per-bar `category`/`primary_promotion`/`promotion_text`, treats `distance_meters` as nullable, and shows a plain greeting when summary data is absent ([model](../fe/lib/features/home/domain/models/home_model.dart), [toolbar rules](../fe/lib/features/home/domain/home_toolbar.dart): venue prompt only when `nearest_venue.distance_meters` < 10 m, else `promo_summary.total` > 0, else greeting). Badges come only from `primary_promotion`; FE no longer searches promotion titles.
- Category pills open `/category/{bars|restaurants|clubs}` ([page](../fe/lib/features/venues/presentation/pages/category_venues_page.dart)), calling `GET /bars` in listing mode: `category` = `bar|restaurant_bar|night_club`, `limit=20`, `offset`, optional `latitude/longitude`, `max_distance` (≤ 50 km, location only), `q`, `min_rating`, `has_promotions`; reads `X-Total-Count`/`X-Has-More`. Search is debounced and stale responses are dropped.
- Shell mounts only the selected tab; Home results, per-tab scroll and Find search/panel/camera/destination/route live in [ShellSession](../fe/lib/core/session/shell_session.dart) (route redrawn from saved points, no directions request). Browsing never prompts for location; check-in explains in Portuguese, then requests it ([explainer](../fe/lib/features/location/presentation/location_permission_explainer.dart)).
- Compatibility: BE first; an older BE lacks the new fields (greeting only, badges hidden) and ignores the extra `/bars` params (no pagination headers, so FE shows one page). Carried forward: benefits/venues (`/me/benefits`), order `bar_name`, read-only contact edit, native-wallet probe stubbed. Tests: [toolbar](../fe/test/features/home/home_toolbar_test.dart), [bloc](../fe/test/features/home/home_bloc_test.dart), [category](../fe/test/features/venues), [shell](../fe/test/ui/shell/shell_lifecycle_test.dart). Device/browser acceptance unverified.

## Latest backend update

- Date: 2026-11-08. Scope: Home/discovery contracts; no migration. Tests: [home discovery](../be/tests/test_home_discovery.py); local SQLite only, no deployment. Service: [venue_discovery](../be/app/bars_and_restaurants/services/venue_discovery.py).
- `GET /home/` adds optional `display_name`, `promo_summary{total,pro_coupons,cashback,promotions,campaigns}` (authenticated only), `nearest_venue{id,name,distance_meters}`, and per-bar `category`, `primary_promotion` (`happy_hour|cashback|promotion`, priority in that order, from stored fields) and `promotion_text`; `rating` is now the real value. Count = remaining Pro coupons + one available cashback wallet + distinct live nearby promotions (cashback promotions only for Pro and only with a funded bar wallet) + distinct live offer campaigns (`promote_happy_hour` or goal `promotion`; generic advertising excluded), counted before the 10-bar carousel limit. Campaign status, dates, budget, `targeting.days/hours` and a narrower `radius_km` are enforced; promotions honour dates, `recurring_days` and daily windows (venue timezone). Nearest venue is by distance, not ad tier. Without coordinates only owned benefits are counted, `nearby_bars` lists ready venues of the user's country (default BR) with null distance, and `nearest_venue` is null.
- `CampaignCreative.promote_happy_hour` (bool, default false) now survives create/update/response; creatives stored before this change read as false and previously discarded flags cannot be recovered.
- `GET /bars` is additive: `latitude/longitude` optional; new `q`, `min_rating`, `has_promotions`, `limit` (≤ 100), `offset`; `Bar` gains `rating`, `primary_promotion`, `promotion_text`, `has_promotions`. Listing mode (any new param, or no coordinates) filters before paging and orders nearest-first, or name then id without location; it returns `X-Total-Count` and `X-Has-More`. Calls with only the old params keep the legacy order and unpaged list.
- Carried forward: `/me/benefits` and contact-change APIs ([dob_95](../be/migrations/versions/dob_95_contact_change_requests.py)), `PUT /me/profile` 409 on contact changes, `GET /orders/user/me` `bar_name`, `defer_payment` false for legacy callers, `/me/cards` needs a fresh PagarMe `token_`, `POST /checkins` needs [c05](../be/migrations/versions/c05_customer_checkins.py). Rollout: DPE → migrated BE → FE via CI/CD.
